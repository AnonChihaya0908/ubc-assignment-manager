# UBC作业管理工具

当前版本：**1.2.0**。

这是一个只在本机运行的 Windows 应用。它会用独立的 Edge 窗口打开你有权访问的 PrairieLearn 或 UBC WeBWorK 页面，读取页面上可见的作业名称和日期，集中显示并在截止前提醒。它不使用教师 API，也不需要 API token。

## 使用

1. 运行 `ubc-assignment-manager-1.2.0-setup.exe`，安装程序会为当前账户安装应用，并创建桌面和开始菜单入口。之后直接从“UBC作业管理工具”入口启动，无需打开 CMD，也无需单独安装 Node.js。应用在屏幕空间足够时以 1440 × 810 的 16:9 窗口打开，较小屏幕会按可用区域等比例缩小。
   从 GitHub 获取源码后，运行 `npm run build:app` 会生成安装包、便携包及 SHA-256 校验文件。安装包和便携包都不含开发者课程数据、Edge 登录资料或微信 SendKey。需要免安装使用时，可以解压完整便携包；请勿只移动其中的 EXE。
2. 点击左侧底部的设置图标，进入“课程与登录”，选择课程并点击“打开登录窗口”。在打开的 Edge 窗口中完成学校网站登录。这个 Edge 窗口使用专用的本地浏览器资料，不会自动继承你平时浏览器的登录状态。
3. 首次启动按引导添加课程，回到应用后点击“立即同步”。它会依次同步全部课程。新安装不会预置他人的课程；引导可以跳过，也能在“设置 → 常规与窗口”重新打开。
4. 在左侧按 PrairieLearn、WeBWorK 或具体课程筛选；上方切换“待完成”“将开放”“已过日期”“已完成”。点击作业行可在右侧查看详情、修改提醒日期或标记完成；较窄窗口会在作业行内显示这些操作。成绩以横条和居中的百分比展示。

课程页面提供分组标题时，“设置 → 课程与登录”会列出可管理的作业类别。可以只在某一门课中取消“管理”开关，例如根据 syllabus 在 CPSC 317 中忽略 `In Class Assignment`。应用不会自行判断类别是否计分。被忽略类别仍保留成绩、日期和手动设置，可在“已忽略”页恢复；它们不会进入待办计数、目录红点、Windows 通知或微信每日汇总。同名类别在其他课程中不受影响。

如果独立 Edge 登录窗口无法同步 PrairieLearn，在你平时登录的浏览器里选中作业表格并复制。回到应用“设置 → 课程与登录”，展开手动导入区域，粘贴后点“导入所选课程”。这会导入作业名称和页面显示的日期；之后自动同步成功时，相同作业代码会合并。

应用和专用 Edge 登录窗口运行期间，每 30 分钟尝试刷新一次已登录课程。它在截止前 24 小时和 3 小时发出 Windows 提醒。关闭主窗口后，后台进程和系统托盘仍运行；双击托盘图标可重新打开窗口，右键菜单可立即同步、暂停或恢复提醒、退出应用。只有从托盘或“设置 → 数据与退出”退出才会停止后台。电脑关机或应用退出时，无法发出提醒。

在“设置 → 常规与窗口”可开启“登录 Windows 后自动启动”。开启后，应用会为当前 Windows 账户登记实际的 `UBC作业管理工具.exe` 路径；下次登录时静默进入系统托盘，不主动弹出主窗口。移动应用文件夹后，设置页会提示路径已失效，可重新开启该选项修复。重复双击程序只会打开主窗口，不会建立第二个提醒后台。

## 软件更新

应用打开时会检查此仓库最新的稳定版 GitHub Release；设置 → 常规与窗口也可以手动检查。发现新版本后，可选择“稍后”或“立即更新并重启”。立即更新会下载与版本号对应的 Windows 便携包及 SHA-256 校验文件，验证后关闭旧版、备份程序文件、安装新版并重新打开。如果新版无法启动，安装程序会恢复旧版。课程、完成状态、提醒配置及专用 Edge 登录资料保存在独立的用户数据目录中，不参与程序文件替换。

当前 GitHub 仓库已公开。应用通过 GitHub 公共 HTTPS API 读取 Release，无需安装 GitHub CLI、登录 GitHub 或提供 token。临时网络错误会自动重试，并区分超时、DNS、连接和 GitHub HTTP 错误。发布更新时须同时上传 `ubc-assignment-manager-版本-windows.zip` 和同名 `.zip.sha256`，且 Release 标签为 `v版本`，例如 `v1.2.0`。目前没有发布 Release 时，应用会显示“暂时没有可安装的发布包”。

应用内安装只在独立解压的便携包中启用。在包含 `.git` 的开发目录运行时，应用仍会检查新版本，但不会覆盖正在开发的源码；请在开发目录外解压发布包后使用应用内更新。

可以在“设置 → 课程与登录”添加其他 PrairieLearn 课程的 `.../pl/course_instance/数字/assessments` 网址，或 UBC WeBWorK 的 `https://webwork.elearning.ubc.ca/webwork2/课程名` 网址。网站图标和目录名称旁的红点表示该平台或课程有已开放且未完成的作业；尚未开放和 WeBWorK 标记已截止的作业不触发红点。

## 个人微信每日提醒

1. 在 [Server酱 Turbo 官网](https://sct.ftqq.com/docs/getting-started/sendkey/)获取并绑定个人微信的 `SCT` SendKey。请勿把密钥发到聊天中。
2. 打开应用“设置 → 提醒与同步”，将 SendKey 填入“个人微信每日提醒”，选择每天的电脑当地时间，勾选启用并保存。
3. 点击“发送测试消息”，确认微信可以收到消息。此按钮会立即发送一条真实的测试消息。

到设定时间后，应用每天发送一次已开放且未完成作业的汇总。若当天设定时间已过，启用后会补发一次；发送失败最多重试两次，每次至少间隔 30 分钟。电脑和应用必须保持运行。作业名称、课程名称和日期会发送给 Server酱；SendKey 只保存在当前账户的本地应用数据目录中，不会显示在应用状态接口中。可在相同设置页关闭提醒或清除密钥。

如果设定时间电脑未开机，当天稍后启动应用会发送当天的汇总；如果直到次日才启动，则按次日时间发送次日汇总，不逐日补发关机期间的旧消息。启用登录 Windows 后自动启动可让后台在登录时恢复。每天最多发送一条成功的自动汇总。托盘或设置页中的“暂停提醒”会暂停 Windows 截止提醒与每日微信汇总，但不会停止课程同步。

“设置 → 提醒与同步”可以修改 Windows 提前提醒小时数、设置跨午夜的免打扰时段，并逐门课程关闭提醒。关闭课程提醒后，该课程不会进入 Windows 通知或微信汇总。免打扰结束或电脑从睡眠恢复后，应用只处理当天尚未成功的汇总；发送记录会区分自动汇总、手动测试、Windows 通知、失败和重试。记录中的“服务已接受”只表示 Server酱接口接受了请求，实际是否到达微信仍需在手机端确认。

如果显示“网络访问被系统或运行环境拒绝”，先在“设置 → 数据与退出”退出应用，再从 Windows 桌面双击“UBC作业管理工具.exe”。在受限的开发环境里启动的后台进程可能无法访问外网；打开文档网页成功，也不能证明该后台进程有网络权限。

## 数据与限制

- 作业数据、微信提醒设置和专用 Edge 登录资料保存在 `%LOCALAPPDATA%\UBC作业管理工具\data`。第一次运行新版时，应用会从便携目录的 `.local-data` 复制现有数据并保留原文件作为恢复副本。不要公开这些目录。未启用个人微信提醒时，应用不会把作业清单发送给 Server酱。
- “设置 → 数据与退出”可以导出带格式版本的 JSON 备份并在新安装中恢复。备份包含课程、缓存作业、手动完成状态、提醒日期覆盖和普通设置；不含 SendKey、Cookie、Edge 登录资料、发送记录，所有课程与作业网址会移除查询参数。导入会替换当前课程与作业，应用会先在本机创建恢复点；恢复后需要重新登录课程，微信凭证不会从备份文件导入。
- 可从 Windows“已安装的应用”或开始菜单卸载。卸载时选择保留个人数据，重装后会继续使用原有课程和设置；选择删除则同时移除课程、浏览器登录资料、提醒设置和开机启动项。
- 页面显示的 `100% until` 是按时得分阶段的结束时间，通常是作业的按时截止时间。其他百分比的 `until` 可能只是早鸟或迟交阶段结束时间，应用不会对它们自动提醒。
- PrairieLearn 页面上的日期没有显示年份，应用按课程学期推算；日期按电脑的当地时间解释。请核对个人延期、改期和时区。
- WeBWorK 的开放中作业只有出现 `Due` 才会自动设置截止提醒。未来作业的 `Will open on` 是开放时间，不会被当作截止时间；已截止作业会单独列出。WeBWorK 明确标注的 PDT/PST 时间会按其时区换算。
- 列表仅包含登录后当前页面可见的作业。网页结构发生变化时，自动同步可能失败；失败不会清空上次的本地数据。
- “已完成”默认根据网页上的 `100%` 成绩判断。可以手动改为未完成或已完成；在“设置 → 常规与窗口”开启“所有完成状态需要手动确认”后，达到 100% 的作业会留在待完成列表顶部，直到手动确认。

## 开发与验证

运行打包后的 `exe` 需要 Windows、Microsoft Edge 和系统自带的 .NET Framework；Node.js 已放在 `runtime` 文件夹里。重新打包或开发时需要 Node.js 22 或更新版本。项目不依赖第三方 npm 包。

```powershell
npm run build:app
npm test
npm run test:browser
node app.js --no-open
```
